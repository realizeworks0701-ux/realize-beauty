# ADR-017: APIドキュメント管理方針

## ステータス

採用（Accepted）

---

## 背景

API仕様は、開発者だけでなく将来の保守担当者や利用者にとっても理解しやすい形で管理する必要がある。

Swagger UI は API の動作確認に優れており、Redoc は読みやすいドキュメントを生成できる。

---

## 決定事項

APIドキュメントは以下の構成で管理する。

- OpenAPI 3.1 を仕様書とする
- Redocly を正式なAPIドキュメントとする
- Swagger UI を動作確認・テスト用途で利用する

OpenAPI のファイルは以下に配置する。

```
docs/api/
```

API仕様は OpenAPI のみを編集し、その他のドキュメントは OpenAPI から生成または参照する。

---

## メリット

- API仕様を一元管理できる
- ドキュメントと実装が一致する
- 保守性が向上する
- 開発者体験（DX）が向上する

---

## デメリット

- OpenAPI の記法を学ぶ必要がある
- API変更時は OpenAPI の更新が必須となる
