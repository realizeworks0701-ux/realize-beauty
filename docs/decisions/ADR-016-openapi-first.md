# ADR-016: OpenAPI First 開発を採用する

## ステータス

採用（Accepted）

---

## 背景

Realize Beauty は API を中心とした設計（API First）で開発を進める。

プロジェクトの成長に伴い、API仕様書と実装を別々に管理すると、仕様と実装の不一致が発生しやすくなる。

そのため、API仕様の「唯一の正」となるドキュメントが必要である。

---

## 決定事項

本プロジェクトでは **OpenAPI First** を採用する。

すべての REST API は、実装より先に OpenAPI へ定義する。

OpenAPI は以下の内容を管理する。

- APIエンドポイント
- リクエストパラメータ
- リクエストボディ
- レスポンス
- ステータスコード
- 認証方式
- エラーレスポンス

Laravel の実装は OpenAPI に従うものとする。

---

## メリット

- API仕様と実装の整合性を保てる
- フロントエンドとバックエンドを並行開発できる
- Swagger UI / Redoc からドキュメントを自動生成できる
- APIクライアントを自動生成できる
- AI（CLINE・ChatGPT）との開発相性が良い

---

## デメリット

- 実装前に仕様を書くため、初期コストが増える
- API変更時は OpenAPI の更新が必須となる
