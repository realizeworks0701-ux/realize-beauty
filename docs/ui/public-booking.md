# Public Booking

## 概要

顧客向けの公開Web予約ページ。サロンごとの公開URL（`/booking/{booking_slug}`）から認証なしで予約を受け付ける。サロンはこのURLをLINEリッチメニュー・Instagram・Googleマップ等に掲載する。

予約キャンセルページ（`/booking/cancel/{booking_token}`）も本書で扱う。

顧客はスマートフォンからアクセスすることを想定し、**モバイルファースト**で設計する（管理画面の「PC優先」方針の例外）。

---

## Route

* `/booking/:slug` — 予約フロー（ステップ式）
* `/booking/cancel/:token` — 予約キャンセルページ

いずれも**認証ガード対象外の公開ルート**。Sanctum 認証・ログイン画面へのリダイレクトは適用しない。

`/booking` 配下のその他のパス（slug / token の欠落・typo 等）には公開ルート用のキャッチオール（meta.public: true）を追加し、PublicLayout の「ページが見つかりません」表示に落とす。既存のキャッチオール（/dashboard → /login リダイレクト）には流さず、顧客に管理画面のログイン画面を見せない。

---

## Layout（PublicLayout）

管理画面の共通レイアウト（[layout.md](layout.md)）は使用せず、公開ページ専用の PublicLayout を新設する。

* サイドバー・管理ヘッダー・ログインユーザー表示なし
* ヘッダーはサロン名のみ（GET /api/public/v1/salons/{booking_slug} から取得）
* 1カラム・中央寄せ（コンテンツ最大幅 480px 目安。PC でも同レイアウト）
* 配色・角丸・フォントは [design-system.md](design-system.md) を踏襲する

---

## Components — 予約フロー（/booking/:slug）

ステップインジケータ（1 メニュー → 2 スタッフ → 3 日時 → 4 お客様情報 → 5 確認）を上部に表示し、1画面1ステップで進める。

* 「戻る」で前ステップへ戻れる
* 前ステップの選択を変更した場合、後続ステップの選択はリセットする（例: メニュー変更で日時選択をリセット）

### Step 1: メニュー選択

* 有効メニュー一覧をカードリストで表示（メニュー名・所要時間・価格。例: カット（60分・¥5,500））
* display_order 昇順
* タップで選択し次へ

### Step 2: スタッフ選択

* 先頭に「指名なし」（既定選択）。「空いているスタッフが担当します」の注記を添える
* 有効スタッフ一覧（氏名のみ）
* タップで選択し次へ

### Step 3: 日時選択

* 日付: DatePicker。選択可能範囲は**今日〜60日先**
* 日付選択で GET availability を呼び、**30分刻み**の空き枠をボタングリッド（3〜4列）で表示する
* 現在時刻+30分より前の枠は表示されない（API が返さない）
* 定休日・空き枠なしの日は「この日はご予約いただけません。別の日をお選びください」の空状態メッセージを表示する
* 枠をタップで選択し次へ

### Step 4: お客様情報入力

| 項目 | UI | 備考 |
|------|----|------|
| お名前 | InputText | 必須・最大100文字 |
| フリガナ | InputText | 必須・最大100文字。カタカナ入力を促すプレースホルダー（例: ヤマダ ハナコ） |
| 電話番号 | InputText（type=tel） | 必須・最大20文字。ハイフンなし可 |

* 文字数上限等の詳細は API バリデーション（openapi.yaml）に従い、422 のメッセージをフィールド単位で表示する
* 電話番号は既存顧客との照合キーになる旨は表示しない（内部仕様のため）

### Step 5: 確認

* 選択内容のサマリを表示: メニュー（所要時間・価格）／担当（スタッフ名 または 指名なし）／日時（開始〜終了予定）／お名前・フリガナ・電話番号
* 「予約を確定する」ボタン → POST reservations
* 送信中はボタンをローディング表示＋無効化（多重送信防止）
* 日時の送信は toIsoWithOffset で ISO 8601（オフセット付き）に変換する（管理側と同じ慣例）

### 完了画面

* 「ご予約を承りました」の見出しと予約内容（menu_name / staff_name / start_at〜end_at）
* キャンセル用URL（`/booking/cancel/{booking_token}`）を表示し、コピーButtonを添える。「キャンセルはこのURLからお手続きください。このページを閉じると再表示できません」の注記を表示する
* **LINE連携案内**（レスポンスの `line` が null でない場合のみ表示。サロンがLINE連携済みの場合に返る）:
  * 友だち追加ボタン（`add_friend_url` へのリンク。LINEブランドカラー #06C755 のボタン）
  * 連携コード（`link_code`）を大きく表示＋コピーButton
  * 手順文: 「1. 友だち追加 → 2. トークに連携コードを送信 → 予約前日にLINEでお知らせが届きます」
  * 連携コードの有効期限（72時間）を小さく添える（例: 「コードの有効期限は72時間です」）
* `line` が null の場合は LINE セクション自体を表示しない
* ステップインジケータは非表示（戻る導線も出さない）

## Components — キャンセルページ（/booking/cancel/:token）

* GET /api/public/v1/bookings/{booking_token} で予約概要を表示: サロン名・メニュー名・担当スタッフ・日時・ステータス
* キャンセル可能（status=reserved かつ開始時刻前）の場合: 「予約をキャンセルする」ボタン（Danger）＋確認ダイアログ → POST cancel
* キャンセル成功: 「予約をキャンセルしました」の完了表示に切り替える
* キャンセル不可の場合はボタンを表示せずエラーメッセージを表示する:
  * キャンセル済み: 「この予約はすでにキャンセルされています」
  * 開始時刻を過ぎている（来店済み等を含む）: 「開始時刻を過ぎた予約はキャンセルできません。サロンへ直接ご連絡ください」
  * token 不正（404）: 「予約が見つかりません」

## API

* GET /api/public/v1/salons/{booking_slug}（サロン名・営業時間・有効メニュー一覧・有効スタッフ一覧）
* GET /api/public/v1/salons/{booking_slug}/availability?date=YYYY-MM-DD&menu_id=N[&user_id=N]（user_id 省略時は指名なし）
* POST /api/public/v1/salons/{booking_slug}/reservations
* GET /api/public/v1/bookings/{booking_token}
* POST /api/public/v1/bookings/{booking_token}/cancel

Pinia の新ストアは追加せず、ページローカル state で管理する。既存の mockAdapter（`services/mock/`）に公開APIのモックを追加する。

---

## Actions

* メニュー・スタッフ・日時の選択（ステップ移動）
* 予約の確定
* キャンセル用URL・連携コードのコピー
* LINE 友だち追加（外部リンク）
* 予約のキャンセル（確認ダイアログあり）

---

## ローディング状態

* 初期ロード（サロン情報取得）: 全体を Skeleton 表示
* 空き枠取得中: 枠グリッド領域を Skeleton 表示（日付・ステップ操作は可能なまま）
* 予約確定・キャンセル送信中: ボタンをローディング表示＋無効化

---

## エラー時挙動

* サロン情報取得 404（不正な slug・無効化されたサロン）: 「ページが見つかりません」の全画面エラー（管理画面への導線は出さない）
* 空き枠取得失敗: 枠グリッド領域にエラーメッセージ＋再試行ボタン
* 予約確定の 422 はレスポンスのエラーキーで分岐する:
  * 顧客情報のエラー（`name` / `kana` / `phone` キー） → Step 4 に戻し、フィールド単位でエラーメッセージを表示する
  * 時間帯系のエラー（`start_at` キー。枠埋まり（Googleカレンダー連携時は外部予定による埋まりを含む）・営業時間外・グリッド外・予約可能範囲外） → Step 3 に戻し、**サーバが返すエラーメッセージをそのまま表示**して空き枠を再取得する（固定文言に置き換えない）
* 429（throttle）: 「アクセスが集中しています。しばらく時間をおいて再度お試しください」を表示する
* キャンセルの 409: 「この予約はキャンセルできません」＋予約概要を再取得して状態表示を更新する
* その他のエラー: Toast で通知する
