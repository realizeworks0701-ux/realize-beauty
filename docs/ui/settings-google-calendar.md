# Settings - Google Calendar

## 概要

Googleカレンダーとの双方向同期を設定する（接続単位モードの選択・Google アカウントの接続／解除・対象カレンダーの選択・接続状態の確認）。

設定画面（[settings.md](settings.md)）の「Googleカレンダー連携」カードから遷移する。

接続すると、RB の予約が対象カレンダーへ書き込まれ、同じカレンダー上の**RB以外の予定**が「外部予定」として RB の空き枠を塞ぐ（[ADR-025](../decisions/ADR-025-google-calendar-sync.md)）。

## Route

`/settings/google-calendar`

## Components

### モード選択カード

サロン単位で接続単位を選ぶ（`salons.google_calendar_mode`）。null = 未設定。

| モード | 表示ラベル | 説明文 |
|------|----|------|
| per_staff | スタッフ別 | 「スタッフがそれぞれ自分のGoogleアカウントを接続します。各スタッフの予約はそのスタッフのカレンダーへ書き込まれ、カレンダー上のRB以外の予定はそのスタッフの空き枠を塞ぎます」 |
| shared | サロン共有 | 「Googleアカウントを1つだけ接続します。全スタッフの予約が1つのカレンダーへ書き込まれ（予定の題名に担当スタッフ名を含む）、カレンダー上のRB以外の予定はサロン全体の空き枠を塞ぎます。店休・全体研修・イベントの登録に向いています」 |

* SelectButton（2択）＋各モードの説明文を併記する。未設定のときはどちらも未選択とし、「接続単位を選んでください」の案内を表示する
* 選択で PUT /api/v1/google-calendar/mode
* **既存の接続が1件以上ある状態でモードを変更する場合は確認ダイアログを出す**: 「接続単位を変更すると、現在のGoogleカレンダー連携はすべて解除されます。解除後、あらためて接続し直してください。Google側に作成済みの予約の予定は削除されませんが、RBのGoogleカレンダーへのアクセス許可は取り消されるため、接続し直す際はGoogleの同意画面での許可が必要です。よろしいですか？」
  * 確定で PUT を送信し、成功後に一覧を再取得する（接続カードは全件「未接続」に戻る）
  * キャンセルで選択を元のモードに戻す（楽観的更新はしない）
  * 一括解除の副作用は「接続を解除」と同一（[連携解除](#連携解除)を参照）
* 接続が0件のときは確認ダイアログなしで切り替える

### 接続カード

GET /api/v1/google-calendar の結果で表示を切り替える。

**per_staff モード**: 有効スタッフ（GET /api/v1/users の is_active）を id 昇順で1行1スタッフの一覧として表示し、各行に当人の接続状態を出す。

**shared モード**: サロン共有接続1件のみをカードとして表示する（スタッフ一覧は表示しない）。

各行／カードは接続状態に応じて3状態を表示する。

| 状態 | 表示 |
|------|------|
| 未接続 | 「未接続」（グレー Tag）＋「Googleと接続」ボタン |
| 接続済み（status=active） | 「接続済み」（Primary Tag）＋ Googleアカウント（google_account_email）＋対象カレンダー（calendar_id）＋最終同期（last_synced_at）＋「カレンダーを変更」「接続を解除」 |
| 要再接続（status=needs_reconnect） | 「要再接続」（警告色 Tag）＋ Googleアカウント＋「Googleと接続」（再接続）ボタン＋「接続を解除」 |

* 最終同期（last_synced_at）が null の場合は「同期待ち」と表示する（接続直後は初回同期がキュー経由のため、すぐには入らない）
* 対象カレンダーは `primary` の場合「メインカレンダー（{google_account_email}）」と表示する。それ以外は **`calendar_id` をそのまま表示する**。RB はカレンダーの表示名を保持しないため（API も返さない）、一覧表示で名称に解決することはできない。名称は「カレンダーを変更」ダイアログの一覧（GET /connections/{id}/calendars）で確認できる旨を注記する
* per_staff モードでは、**ログイン中のユーザー自身の行でのみ「Googleと接続」ボタンを有効化**する。他スタッフの行は状態表示のみとし、ボタンの代わりに「本人がログインして接続してください」の注記を表示する（OAuth の認可はアカウント本人が行うため）
* shared モードの接続はサロンに1件。既に接続済みの場合「Googleと接続」ボタンは表示しない（別アカウントへ切り替えるには一度解除する）

### 接続フロー（Googleと接続）

1. 「Googleと接続」ボタン → POST /api/v1/google-calendar/auth-url
2. レスポンスの認可URLへ**同一タブで遷移**する（別タブは復帰時のパラメータ処理が二重になるため使わない）
3. Google の同意画面でアカウント選択・権限許可
4. Google → API（`{API_URL}/api/v1/google-calendar/callback`）→ SPA へ 302 リダイレクトで本ページに戻る

* ボタン押下から遷移までは押下ボタンをローディング表示＋無効化する（多重発行防止）
* 認可URL取得に失敗した場合は Toast で通知し、遷移しない

#### 復帰時のクエリパラメータ処理

| パラメータ | 挙動 |
|------|------|
| `?connected=1` | 成功 Toast（「Googleカレンダーと接続しました」）を表示し、一覧を再取得する |
| `?error={code}` | エラー Toast を表示し、一覧を再取得する（接続済みの他の行を正しく表示するため） |
| なし | 通常表示 |

* 処理後は `router.replace` でクエリパラメータを除去し、リロードで Toast が再表示されないようにする
* `error` の値ごとの文言は API 設計に従う。**未知の値は汎用文言（「Googleとの接続に失敗しました。もう一度お試しください」）にフォールバック**し、値をそのまま画面に出さない

### 対象カレンダー選択

* 接続済みカードの「カレンダーを変更」→ ダイアログを開き、GET /api/v1/google-calendar/connections/{id}/calendars でカレンダー一覧を取得して Select に表示する（取得中は Skeleton）
* 既定かつ推奨は `primary`（メインカレンダー）。Select の初期値は現在の calendar_id
  * `primary` はエイリアスであり、カレンダー一覧は実 id（アカウントのメールアドレス）を返す。そのため現在の calendar_id が `primary` の場合、Select の初期値は一覧の**メインカレンダーのエントリ**（primary フラグが立っている行）に解決して選択状態にする（文字列一致で照合すると初期値が未選択になる）
  * Select のラベルはカレンダー一覧が返す表示名を使う。この表示名は選択のためだけに使い、**保存も保持もしない**（D10。接続カード側は calendar_id を表示する）
* **`primary` 以外を選択した場合、ダイアログ内に警告メッセージを常時表示する**（Message コンポーネント・警告色）:
  > 専用カレンダーを選ぶと、そのカレンダーに入っている予定しか読み取れません。メインカレンダーの私用予定は空き枠に反映されず、私用の予定がある時間にもWeb予約が入る可能性があります。私用予定も空き枠に反映したい場合はメインカレンダーを選んでください。
* 保存で PUT /api/v1/google-calendar/connections/{id}
* 保存時の確認ダイアログ: 「対象カレンダーを変更すると、これまでに取り込んだ外部予定はいったん破棄され、新しいカレンダーの予定を取り込み直します。**これまでのカレンダーに作成済みの予約の予定は削除され、新しいカレンダーへ書き直されます**。よろしいですか？」
  * **連携解除（後述）とは方針が異なる**（意図的な非対称）。カレンダー変更は同じGoogleアカウント内での移し替えのため、旧カレンダーに予約の予定を残すと持ち主のいない予定になり、それをスタッフが手動削除したときにRBの生きた予約がキャンセル扱いになる事故につながる。そのため旧カレンダー側は削除する（[ADR-025](../decisions/ADR-025-google-calendar-sync.md)）
* 成功後は Toast＋一覧を再取得する（最終同期は「同期待ち」に戻る）

### 連携解除

* 「接続を解除」ボタン（Danger・接続済み／要再接続の場合のみ表示）
* 確認ダイアログ: 「接続を解除すると、このカレンダーへの予約の書き込みと、カレンダー上の予定の取り込みが停止します。**Google側に作成済みの予約の予定は削除されません**（不要な場合はGoogleカレンダーから手動で削除してください）。また、**取り込み済みの外部予定は削除され、その時間帯もWeb予約で空き枠として表示されるようになります**。あわせて**RBのGoogleカレンダーへのアクセス許可も取り消されます**（Googleアカウントの「サードパーティ アクセス」からRBが消えます）。再び連携するには、Googleの同意画面からあらためて許可が必要です。よろしいですか？」
* 確定で DELETE /api/v1/google-calendar/connections/{id} → 当該行を「未接続」表示に戻す
* カレンダー変更が旧カレンダーの予約の予定を削除するのに対し、解除では削除しない。解除はサロンが連携そのものをやめる操作であり、Google側に残った予約の予定はサロンの記録として意味を持つため（[ADR-025](../decisions/ADR-025-google-calendar-sync.md)）
* status=needs_reconnect の接続でも解除は成功する（Google側の後始末が失敗しても RB 側の解除は完遂するため）。「Google側でアクセスを取り消したので RB からも解除できない」状態にはならない

### 要再接続の導線

* status=needs_reconnect は、Google 側でアクセス権が取り消された・再認可が必要になった状態。同期は停止している
* カード上部に警告 Message を表示する: 「Googleとの接続が切れています。予約の書き込みと外部予定の取り込みが停止しています。再接続してください」
* 「Googleと接続」ボタンで通常の接続フローをやり直す（同じ Google アカウントで再認可すると既存の接続が更新される）
* per_staff モードで**当人以外**が閲覧している場合はボタンを出さず、「{スタッフ名}さんの再接続が必要です」の注記のみ表示する

### 設定手順ガイド

未設定・未接続のときにページ下部へ手順リストを表示する（接続済みのときは折りたたみ）。

1. 接続単位（スタッフ別／サロン共有）を選ぶ
2. 「Googleと接続」からGoogleの同意画面へ進み、カレンダーへのアクセスを許可する
3. 同意画面で「このアプリはGoogleで確認されていません」という警告が表示される場合がある。Googleの審査完了前は表示される想定のため、「詳細」→「（アプリ名）に移動」から続行する（[ADR-025](../decisions/ADR-025-google-calendar-sync.md)）
4. 接続後、対象カレンダーがメインカレンダーになっていることを確認する（私用予定を空き枠に反映するため、メインカレンダーを推奨）
5. 接続すると、以降のRBの予約がGoogleカレンダーに自動で追加され、予約の時間変更・キャンセルも反映される
6. Googleカレンダー側でRB以外の予定を入れると、その時間はRBの空き枠から外れ、予約カレンダーに「外部予定」として時刻のみ表示される（予定の内容はRBに保存されない）
7. Googleカレンダー側でRBの予約の予定を移動すると、空いていればRBの予約も移動する。移動先が埋まっている場合はRBの予約時間が優先され、Google側が元の時間に戻る

* 「RBに保存されるのは外部予定の開始・終了時刻のみで、予定のタイトルや参加者は保存しない」旨をガイド内に明記する（プライバシー配慮）
* 対象カレンダーの表示について、「メインカレンダー以外を選んだ場合はカレンダーIDがそのまま表示される。カレンダー名は『カレンダーを変更』から確認できる」旨を添える（D10・表示名を保持しないため）

#### 開発・検証時の注意（サロン向けの案内には出さない）

手順3の「確認されていません」警告と混同しやすいが、**OAuth同意画面の公開ステータスが Testing（テストモード）の間は refresh_token が7日で失効する**。
すべての接続が7日ごとに「要再接続」に落ち、同期が毎週止まる。これは実装の不具合ではなく Google の仕様のため、
**開発・検証段階から公開ステータスは「In production（未確認）」にする**（[ADR-025](../decisions/ADR-025-google-calendar-sync.md) §1）。
手順3の警告が出るのは「In production かつ未確認」の状態であり、Testing とは別物である。

## API

* GET /api/v1/google-calendar（モード＋接続一覧。メール・対象カレンダー・状態・最終同期。トークンは返さない）
* PUT /api/v1/google-calendar/mode
* POST /api/v1/google-calendar/auth-url
* GET /api/v1/google-calendar/connections/{id}/calendars
* PUT /api/v1/google-calendar/connections/{id}
* DELETE /api/v1/google-calendar/connections/{id}
* GET /api/v1/users（per_staff モードのスタッフ一覧）

GET /api/v1/google-calendar/callback は Google からのブラウザリダイレクトで呼ばれるため、SPA からは呼ばない。

Pinia の新ストアは追加せず、ページローカル state で管理する。

## Actions

* 接続単位モードの選択（既存接続ありの場合は確認ダイアログあり）
* Googleと接続（認可URL取得 → 遷移）
* 対象カレンダーの変更（確認ダイアログあり）
* 接続の解除（確認ダイアログあり）
* 再接続

---

## 状態

| 状態 | 表示 |
|------|------|
| ローディング（初期取得中） | モード選択・接続カード領域を Skeleton 表示 |
| 未設定（mode=null） | モード選択カードを未選択で表示。接続カードは表示せず「接続単位を選ぶと接続できます」の案内を出す |
| 接続中（1件以上 active） | モード選択＋接続カード。設定手順ガイドは折りたたみ |
| 要再接続あり | 該当カードに警告 Message＋再接続導線 |
| エラー | 取得失敗時はエラーメッセージ＋再読み込みボタン |

* per_staff モードでスタッフが0人の場合は接続カードの代わりに空状態メッセージ（PrimeIcons 使用）を表示する
* 送信中（モード変更・カレンダー変更・解除）は該当ボタンをローディング表示＋無効化する

---

## エラー時挙動

* 取得失敗時はエラーメッセージ＋再読み込みボタンを表示する
* 認可URL取得の失敗: Toast で通知し、Googleへ遷移しない
* 復帰時の `?error=`: Toast で通知し、一覧を再取得する。未知の値は汎用文言にフォールバックする
* モード変更の失敗: Toast で通知し、選択を元のモードに戻す
* カレンダー一覧の取得失敗: ダイアログ内にエラーメッセージ＋再試行ボタンを表示する（ダイアログは閉じない）
* カレンダー変更・解除の失敗: Toast で通知する
* モード変更・接続・カレンダー変更・解除の成功は Toast で通知する
