# Feature Locked

## 概要

契約プランに含まれない機能へアクセスしたときに表示する、アップグレード導線の画面（[ADR-029](../decisions/ADR-029-subscription-billing.md)）。

ルータの `beforeEach` が `meta.feature` を持つルートを検査し、`user.features` に無い機能なら本画面へ振り替える。**これは案内のための画面であり、セキュリティ境界ではない**。実際の遮断は必ずバックエンドの 403（`FeatureRequiredException`）が担う。

「404 で存在ごと隠す」ではなく「機能名と必要プランを明示する」方針を採る。契約すれば使えるものを隠しても解約や問い合わせを増やすだけで、利用者の利益にならないため。

---

## Route

`/plan-required/:feature`

* `:feature` は Feature のキー（customer / medical_record / photo / reservation / google_calendar / line / ai_summary / analytics）
* 認証ルート（`meta.public` は付けない）。未ログインなら通常どおりログイン画面へ振り替わる
* `meta.feature` は付けない（このルート自体が振り替え先のため、付けると無限ループになる）

---

## Components

### PageHeader

* タイトル: 対象機能のラベル（例: 「予約管理」）。鍵アイコン（`pi pi-lock`）を添える
* サブタイトル: 「現在のご契約プランではこの機能をご利用いただけません」

### FeatureUpsell（共通コンポーネント）

アップグレード導線の本体。本画面のほか、ダッシュボードの分析カード・カルテ詳細のAI要約でも `compact` 表示で再利用する（画面ごとに文言を書き分けない）。

* 見出し: 「この機能は{必要プラン}プラン以上でご利用いただけます」
  * どのプランにも含まれない機能の場合は「{機能名}は現在のプランではご利用いただけません」にフォールバックする
* 説明: そのプランで**新たに**使えるようになる機能を「・」区切りで並べる（例: 「予約管理・Googleカレンダー連携・LINE連携をご利用いただけます。」）。金額の比較や訴求文は置かず、判断材料はプラン一覧（[settings-plan.md](settings-plan.md)）に集約する
* ボタン: 「{必要プラン}プランを見る」→ `/settings/plan` へ遷移

必要プラン・機能の対応はフロントの `useFeatures`（`config/billing.php` の写し）で解決する。表示のためだけの複製であり、判定の正はサーバにある。

### 未知の feature キー

URL を直接叩かれた場合に備え、`:feature` が既知のキーでなければ「指定された機能が見つかりませんでした。」＋「ダッシュボードへ戻る」リンクのみを表示する。**パラメータの値をそのまま画面に出さない**。

---

## API

呼ばない。表示に必要な情報（`plan` / `features`）はログイン時に取得済みの `user` から得る。

---

## Actions

* プランを見る（/settings/plan へ遷移）
* ダッシュボードへ戻る（未知の feature キーのときのみ）
