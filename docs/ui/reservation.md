# Reservation Calendar

## 概要

サロン側の予約カレンダー。日表示（縦＝時間軸・横＝スタッフ列）で予約を確認・登録・変更する。

---

## Route

`/reservations`

---

## Components

### Header

* 前日ボタン（＜）
* 今日ボタン
* 翌日ボタン（＞）
* DatePicker（表示日を直接選択）
* 表示日（例: 2026年7月14日（火））

---

### Calendar Grid（自前実装・CSS grid）

外部カレンダーライブラリは使用しない（[ADR-023](../decisions/ADR-023-reservation-core.md)）。

* 縦軸: 時間（30分刻み）
* 横軸: スタッフ列（GET /api/v1/users の is_active スタッフ全員。列順は id 昇順）
* 左端に時刻ラベル列（1時間ごとに表示）

#### 表示レンジ

* 表示日の曜日の営業時間（GET /api/v1/business-hours）から導出し、前後1時間のパディングを加え、時間単位に丸める
  * 例: 営業 09:00〜19:00 → 表示 08:00〜20:00
* 表示日の予約に上記レンジ外のものがある場合、当日の全予約の min(start_at)〜max(end_at) を包含するようレンジを拡張する（時間単位に丸める）。営業時間外の予約登録が許可されているため（[ADR-023](../decisions/ADR-023-reservation-core.md)）、レンジ外の予約が非表示になり見落とされることを防ぐ
  * 例: 営業 09:00〜19:00 の日に 21:30〜22:30 の予約がある → 表示 08:00〜23:00
* 営業時間外のセルはグレーアウト（背景 #F0E4E8 系の淡色）。**クリックは可能**（時間外の手動予約を許容するため）
* 定休日（is_closed=true）は全時間帯グレーアウトし、表示レンジはデフォルト（09:00〜19:00 ±1h）を基準に同様の拡張を適用する

#### 予約ブロック

* 位置・高さは start_at〜end_at から算出（30分＝1行。端数は分単位で比例配置）
* 表示内容: 顧客名・メニュー名・開始〜終了時刻（高さが足りない場合は顧客名のみ）
* status 別色（design-system.md のパレットに合わせる）

| Status | 色 |
|--------|----|
| reserved | Primary（#D86C8A 系・ピンク） |
| visited | Mauve（#B98AA6 系） |
| cancelled | グレー（#9A8D91 系・半透明＋テキスト打ち消し線） |
| no_show | Cream（#CBA96D 系・半透明） |

* cancelled / no_show はダブルブッキング判定外のため他の予約と重なりうる。同一スタッフ列で時間帯が重なるブロックは、列幅を等分して横並びに表示する
* クリックで編集ダイアログを開く

#### 外部予定ブロック

Googleカレンダー連携（[ADR-025](../decisions/ADR-025-google-calendar-sync.md)・[settings-google-calendar.md](settings-google-calendar.md)）で取り込んだ、RB 由来でない予定（busy ブロック）を表示する。未連携のサロンでは表示されない。

* 位置・高さは予約ブロックと同じ算出（start_at〜end_at）
* 表示内容は「外部予定」のラベルと開始〜終了時刻のみ。**予定のタイトルは表示しない**（表示を控えるのではなく、RB がタイトル・説明・参加者を一切保存せず API も返さないため**表示できない**。プライバシー配慮。[ADR-025](../decisions/ADR-025-google-calendar-sync.md)）
* 色はグレー（#9A8D91 系・淡色）。予約ブロックと視覚的に区別する
* 編集ダイアログは開かない（RB の予定ではなく、RB から変更できないため）。ただしブロック上のクリックは**空セルと同様に新規登録ダイアログを開く**（クリックしたスタッフ・時刻をプリセット）。管理側の予約登録は busy でもブロックしない仕様（[ADR-025](../decisions/ADR-025-google-calendar-sync.md)）のため、外部予定に覆われた時間帯もカレンダーから起票できる必要がある。営業時間外セル（前述）と同じ扱い
* スタッフ別（per_staff）モードは当該スタッフの列のみに表示する。サロン共有（shared）モードはサロン全体を塞ぐ意味論のため全スタッフ列に表示する
* 外部予定と予約は重なりうる（管理側の予約登録は busy でもブロックしない。公開Web予約のみ不可）。同一スタッフ列で重なるブロックは予約ブロックと同じく列幅を等分して横並びに表示する
* 終日予定は当日の表示レンジ全体を覆うブロックとして表示する（この場合も上記のとおりクリックで新規登録ダイアログを開けるため、当該スタッフ列からの起票が塞がることはない）

#### 空セル

* クリックで新規登録ダイアログを開く（クリックしたスタッフ・時刻をプリセット）

### ReservationFormDialog（新規・編集共通）

| 項目 | UI | 備考 |
|------|----|------|
| 顧客 | Select（検索可能） | 既存 customerService.list を利用（keyword検索）。必須 |
| メニュー | Select | is_active=true のみ表示。選択肢に所要時間・価格を併記（例: カット（60分・¥5,500））。必須 |
| 担当スタッフ | Select | GET /api/v1/users。必須 |
| 開始日時 | DatePicker（show-time） | 必須。分は5分刻み入力 |
| メモ | Textarea | 任意・最大2000文字 |
| ステータス | Select | **編集時のみ表示**（reserved / visited / cancelled / no_show） |

* 終了時刻は入力しない（選択メニューの所要時間から「終了予定 11:00」を参考表示する）
* 日時の送信は toIsoWithOffset（既存 RecordFormPage の慣例）でISO 8601（オフセット付き）に変換する
* 編集時のフッター: 削除（誤登録用・確認ダイアログあり）／キャンセル／保存
* 新規時のフッター: キャンセル／登録

## API

* GET /api/v1/reservations?from=YYYY-MM-DD&to=YYYY-MM-DD（表示日1日分: from=to=表示日）
* POST /api/v1/reservations
* PATCH /api/v1/reservations/{id}
* DELETE /api/v1/reservations/{id}
* GET /api/v1/users
* GET /api/v1/menus?is_active=true
* GET /api/v1/business-hours
* GET /api/v1/google-calendar/busy-blocks?from=YYYY-MM-DD&to=YYYY-MM-DD（外部予定ブロック。表示日1日分: from=to=表示日）

外部予定ブロックは専用エンドポイントで取得する（GET /reservations には同梱しない）。レスポンスは `start_at` / `end_at` / `user_id` のみで、**タイトル等の内容は含まれない**（RB に保存していないため）。`user_id` が null の要素は shared モードの外部予定＝サロン全体を塞ぐ意味であり、全スタッフ列に表示する。予約一覧とは独立に取得するため、取得に失敗した場合も予約カレンダー本体は表示する（下記「エラー時挙動」）。

未連携のサロンでは空配列が返る（エラーにはしない）。

Pinia の新ストアは追加せず、ページローカル state で管理する。

---

## Actions

* 日付移動（前日／今日／翌日／DatePicker）
* 予約登録（空セルクリック）
* 予約編集・ステータス変更（予約ブロッククリック）
* 予約削除（編集ダイアログ内）

---

## 空状態

* 表示日に予約が1件もない場合もグリッドは表示する（空セルから登録できるようにする）
* スタッフが0人の場合はグリッドの代わりに空状態メッセージ（PrimeIcons 使用）と説明文を表示する
* メニューが0件の場合、新規ダイアログ内に「メニューを登録してください」の案内と /settings/menus への導線を表示する

---

## エラー時挙動

* 一覧取得失敗: グリッド領域にエラーメッセージ＋再読み込みボタンを表示（Toast併用）
* 登録・更新の 422: ダイアログは閉じず、フィールド単位でエラーメッセージを表示する。ダブルブッキング（`指定した時間帯は既に予約が入っています。`）は開始日時フィールドのエラーとして表示する
* 外部予定の取得失敗: 予約カレンダーは通常表示のまま、外部予定ブロックを表示せず Toast で通知する（予約業務を止めない）
* 削除失敗・その他のエラー: Toast で通知する
* 保存成功: ダイアログを閉じ、Toast 表示後にカレンダーを再取得する
